# Шаблон: чёрно-белый лог, несколько чёрных кривых в одной дорожке

Применять, когда скан 1-битный (или серый) и в дорожке больше одной чёрной линии: сплошная + пунктир,
плюс тонкие линии температуры, рамка, сетка. Старый режим (чистка сетки + `style`) на таких логах даёт
1–13 % совпадения с исполнителем; режим по толщине штриха — 99–100 % (проверено, см. таблицу внизу).

## 1. Почему старый режим ломается

После открытия 3×3 толстая кривая, линия температуры (2–4 px) и жирные линии сетки остаются одной связной
маской. Путь уходит на самую гладкую линию (температуру) или прилипает к вертикальной линии сетки.
На линиях сетки появляются ложные горизонтальные «усы».

## 2. Порядок работы

1. `scan_info`, `scan_crop` — шапка, шкалы, глубины. Ничего не выдумывать: непрочитанное пометить.
2. Увеличить кусок дорожки в 3 раза и посмотреть линии глазами: какая сплошная, какая пунктир, какая толще.
3. Померить толщины: гистограмма `strokes.stroke_width` по дорожке без сетки
   (`strokes.width_and_grid`). Толстая кривая обычно 5–7 px, тонкие линии и пунктир-тире 3–4 px, сетка 1–2 px.
4. Написать задание (блок ниже). Порядок кривых в дорожке: **сначала сплошная толстая, потом пунктир**.
5. Сначала прогнать окно 300 ft (`"interval"`), посмотреть overlay. Только потом весь интервал.
6. Если для этого типа лога есть готовая задача в `data/training/` — проверить настройки цифрами:
   `python tools/eval_width.py <API> <grid> "<кривая>=solid" "<кривая>=dashed"`. Цель — ≥ 95 %.
7. Посмотреть overlay по всей глубине. Что не посмотрено — так и написать.

## 3. Блок задания (проверенные значения для логов 200 dpi, 1:240)

```json
{"name": "Density Porosity (pu)", "min": 30, "max": -10, "seed_x": 1215,
 "style": "solid",  "width": [4], "core": 5, "ink_reward": 0.5}
{"name": "Neutron Porosity (pu)", "min": 30, "max": -10, "seed_x": 1085,
 "style": "dashed", "width": [4], "core": 5, "ink_reward": 1.5, "core_gain": 2.0}
```

| Параметр | Что делает |
|---|---|
| `width: [lo]` или `[lo, hi]` | берутся только линии толщиной от `lo` (до `hi`) px; сетка снимается как прямые линии |
| `core` | толщина, с которой линия считается «своей»: путь получает выигрыш за толстый штрих |
| `core_gain` | сила этого выигрыша (пунктиру — 2.0) |
| `ink_reward` | выигрыш за пройденные чернила: путь идёт в пик, а не срезает его (сплошная 0.5, пунктир 1.5) |
| `style: dashed` | пунктир ищется среди коротких отдельных штрихов; сплошные линии отсеиваются |
| `dash_max` | наибольшая длина штриха пунктира, px (по умолчанию 24) |
| `seed_x` | x кривой в начале интервала; не ставить на линию сетки |

Gamma Ray — `solid`, Caliper — `dashed`, с теми же числами.

## 5. Где шаблон не подошёл (нужен свой набор чисел)

* 19531799 (DPOR / CNPOR / DCAL): с теми же числами 21–23 % на пористости, 80 % на DCAL. Толщины и типы линий
  там другие — их надо померить (шаг 3), а не переносить вслепую.
* Тонкие линии температуры, dTemp, Minute mark этим шаблоном не обводятся.
* Пунктир срезает отдельные выбросы там, где штрихи касаются сплошной линии (сливаются с ней в одну компоненту).

## 6. Правило пополнения

Каждый новый тип лога → прогон `eval_width.py` на готовой задаче из базы → строка в таблицу раздела 4 или 5
с числами. Настройки без проверки на эталоне в шаблон не записывать.
