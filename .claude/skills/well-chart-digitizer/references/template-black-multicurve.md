# Шаблон: чёрно-белый лог, несколько чёрных кривых в одной дорожке

Применять, когда скан 1-битный (или серый) и в дорожке больше одной чёрной линии: сплошная + пунктир,
плюс тонкие линии температуры, рамка, сетка. Старый режим (чистка сетки + `style`) на таких логах даёт
1–13 % совпадения с исполнителем; режим по толщине штриха — 99–100 % (проверено, см. таблицу внизу).

## 1. Почему старый режим ломается

После открытия 3×3 толстая кривая, линия температуры (2–4 px) и жирные линии сетки остаются одной связной
маской. Путь уходит на самую гладкую линию (температуру) или прилипает к вертикальной линии сетки.
На линиях сетки появляются ложные горизонтальные «усы».

## 2. Порядок работы

1. `scan_info`, `scan_crop` — шапка, шкалы, глубины. Ничего не выдумывать: непрочитанное пометить.
2. Увеличить кусок дорожки в 3 раза и посмотреть линии глазами: какая сплошная, какая пунктир, какая толще.
3. Померить толщины: гистограмма `strokes.stroke_width` по дорожке без сетки
   (`strokes.width_and_grid`). Толстая кривая обычно 5–7 px, тонкие линии и пунктир-тире 3–4 px, сетка 1–2 px.
4. Написать задание (блок ниже). Порядок кривых в дорожке: **сначала сплошная толстая, потом пунктир**.
5. Сначала прогнать окно 300 ft (`"interval"`), посмотреть overlay. Только потом весь интервал.
6. Если для этого типа лога есть готовая задача в `data/training/` — проверить настройки цифрами:
   `python tools/eval_width.py <API> <grid> "<кривая>=solid" "<кривая>=dashed"`. Цель — ≥ 95 %.
7. Посмотреть overlay по всей глубине. Что не посмотрено — так и написать.

## 3. Блок задания (проверенные значения для логов 200 dpi, 1:240)

```json
{"name": "Density Porosity (pu)", "min": 30, "max": -10, "seed_x": 1215,
 "style": "solid",  "width": [4], "core": 5, "ink_reward": 0.5}
{"name": "Neutron Porosity (pu)", "min": 30, "max": -10, "seed_x": 1085,
 "style": "dashed", "width": [4], "core": 5, "ink_reward": 1.5, "core_gain": 2.0}
```

| Параметр | Что делает |
|---|---|
| `width: [lo]` или `[lo, hi]` | берутся только линии толщиной от `lo` (до `hi`) px; сетка снимается как прямые линии |
| `core` | толщина, с которой линия считается «своей»: путь получает выигрыш за толстый штрих |
| `core_gain` | сила этого выигрыша (пунктиру — 2.0) |
| `ink_reward` | выигрыш за пройденные чернила: путь идёт в пик, а не срезает его (сплошная 0.5, пунктир 1.5) |
| `style: dashed` | пунктир ищется среди коротких отдельных штрихов; сплошные линии отсеиваются |
| `dash_max` | наибольшая длина штриха пунктира, px (по умолчанию 24) |
| `seed_x` | x кривой в начале интервала; не ставить на линию сетки |

Gamma Ray — `solid`, Caliper — `dashed`, с теми же числами.

## 5. Где шаблон не подошёл (нужен свой набор чисел)

* 19531799 (DPOR / CNPOR / DCAL): с теми же числами 21–23 % на пористости, 80 % на DCAL. Толщины и типы линий
  там другие — их надо померить (шаг 3), а не переносить вслепую.
* Тонкие линии температуры, dTemp, Minute mark этим шаблоном не обводятся.
* Пунктир срезает отдельные выбросы там, где штрихи касаются сплошной линии (сливаются с ней в одну компоненту).

## 6. Правило пополнения

Каждый новый тип лога → прогон `eval_width.py` на готовой задаче из базы → строка в таблицу раздела 4 или 5
с числами. Настройки без проверки на эталоне в шаблон не записывать.

## 7. Сначала — опись всего скана (обязательно, до первой обводки)

Один TIFF обычно содержит несколько секций: обзорная 1:600, основная 1:240, Repeat, отдельные проходы (Sand).
У каждой секции своя шапка, свои глубины и свои кривые. Порядок:

1. `scan_info` → по доле чернил найти границы секций; посмотреть шапку каждой (`scan_crop`).
2. Выписать таблицу: секция, строки скана, масштаб, глубины, все кривые из шапки. Это список работ.
3. На каждую секцию — своё задание `data/jobs/<имя>_<секция>.json`. Глубины: `python tools/depth_refs.py`
   (ищет толстые линии сетки от одной подписанной отметки; для 1:600 — `--thick 2`).
4. Для 1:600 (≈4 px/ft) всем кривым ставить `"zigzag": true`, сплошным `"ink_reward": 1.0` — иначе срезаются пики.
5. Склеить секции в один проект: `python tools/merge_improj.py <выход.improj> <a.improj> <b.improj> ...`
   и открыть его в редакторе — человек видит весь скан сразу.
6. В отчёте перечислить каждую кривую из описи: обведена / черновик / не обведена. Молчать о пропущенном нельзя.

Проверено на BAGGETT OZ "G" #2-116 F (5 секций, эталона нет): Sand и Repeat с числами раздела 3 легли по линиям;
1:600 без `zigzag` срезала пики Gamma Ray, с `zigzag` — идёт по пикам (оценка глазами, не в процентах).

## 8. Распознавание типа линии: `"style": "auto"` (2026-11-25)

Вместо ручных `style`/`width`/`core` можно написать кривой `"style": "auto"` — программа сама посмотрит линию
от `seed_x` (первые ~700 строк) и выберет режим (`src/wellcurves/lines.py`):

| Что увидела | Режим |
|---|---|
| длинная связная линия (доля длинных кусков ≥ 0.5), толщина ≥ 3.5 px | сплошная по толщине: `width [w-1]`, награда за штрих ожидаемой толщины (`stroke_w`) |
| короткие штрихи (< 0.5) | пунктир: `dashed`, `dash_max` по длине штриха |
| тоньше 3.5 px | тонкая → старый режим |
| лежит на линии сетки | прямая (Bit Size) → старый режим |
| не нашла / «щупы» двух кривых сошлись | старый режим |

Сплошные обводятся раньше пунктиров автоматически. Что распознано — `output/<имя>/line_styles.json`.

Проверка на всей базе (220 кривых, окно 400 ft, старт — положение эталона в начале окна):

| | средняя | медиана | ≥ 95 % | ≥ 80 % | < 20 % |
|---|---|---|---|---|---|
| старый режим | 41.9 % | 31.2 % | 41 | 52 | 90 |
| `auto` | **47.9 %** | **39.3 %** | **56** | **73** | **81** |

Лучше на 20+ п.п. — 29 кривых, хуже на 20+ п.п. — 13 (тонкие сплошные на густой сетке, газовые кривые,
47536158_2). Правило «щупы сошлись → старый режим» добавлено против этих провалов, **на базе не измерено**
(прогон остановлен из-за нехватки памяти).

Потолок (тип линии взят из-под обводки исполнителя, `quick_eval.py --oracle`) на 10539239 + 19531799:
средняя 42.7 → 68.7 %. Значит, главный резерв точности — распознавание, сейчас оно совпадает с эталоном в 64 %
(`tools/eval_lines.py`).

Исправления обводки, найденные по ходу (действуют и при ручных настройках `width`):
* стык листов скана и отрезки шире 60 % дорожки убираются из маски — по ним путь «переезжал» на чужую кривую;
* выигрыш за толстый штрих ограничен — заливка/штриховка больше не перетягивает путь.

Инструменты: `tools/line_profile.py` (как выглядит линия каждой кривой под обводкой исполнителя),
`tools/eval_lines.py` (точность распознавания), `tools/quick_eval.py --auto | --oracle`,
`tools/ref_vs_auto.py` (эталон и автообводка одной кривой на одной картинке).
